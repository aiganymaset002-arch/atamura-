# Сервер ATA MURA на Supabase

Без сервера приложение работает на одном устройстве. С сервером у каждого пользователя свой аккаунт,
а публикации, проекты, музей, новости, журнал, курсы и заказы видны на всех устройствах:
участник публикует историю на своём iPhone, редактор одобряет её на своём — и она появляется в ленте у всех.

Можно использовать тот же проект Supabase, что и KKSU: таблицы ATA MURA называются `atamura_*`
и не пересекаются с таблицами KKSU. Адрес и ключ проекта KKSU уже подставлены в приложение по умолчанию.

## 1. Создать таблицы

1. Откройте проект в https://supabase.com → **SQL Editor → New query**.
2. Скопируйте всё содержимое [`schema.sql`](schema.sql) и нажмите **Run** → «Success. No rows returned».

## 2. Настроить вход

**Authentication → Sign In / Providers → Email** — включено. На время тестирования можно выключить
**Confirm email**; если оставить, пользователь сначала подтверждает email по ссылке из письма.
Для реальных писем подключите свой SMTP (**Authentication → Emails → SMTP Settings**).

## 3. Подключить приложение

1. В приложении: **Профиль → Настройки → Сервер ATA MURA → Подключить сервер**.
   Если проект другой — замените Project URL и Publishable key (Settings → API в Supabase).
   Секретный ключ `service_role` в приложение не добавлять никогда.
2. Выйдите и зарегистрируйтесь / войдите заново — аккаунт создастся на сервере (как обычный участник).

## 4. Назначить себя владельцем и задать пароль админки

Это делается только в Supabase — из приложения стать администратором нельзя никому.

1. **SQL Editor → New query**, выполните (подставьте свой email из приложения и придумайте пароль админки,
   минимум 10 символов, буквы и цифры; не используйте пароль от аккаунта):

   ```sql
   select public.atamura_set_owner('ваш-email@example.com', 'ваш-пароль-админки');
   ```

2. Нажмите **Run**. После этого очистите запрос в редакторе, чтобы пароль не остался в истории
   (**SQL Editor → удалить сохранённый запрос**, если он сохранился).
3. В приложении выйдите и войдите снова — появится щит админ-панели. Откройте его и введите пароль админки.
4. В админке: «Профиль → Настройки → Загрузить стартовые темы, места и курсы на сервер».

Сменить пароль админки — та же команда с новым паролем (все открытые сессии админки закроются).
Владелец может быть только один: если выполнить команду с другим email, прежний владелец станет участником.

## Как устроен доступ

| Что | Кто видит | Кто меняет |
|---|---|---|
| Опубликованные истории, проекты, места, музей, исследования | все участники | автор (и владелец (админ)) |
| Материалы на модерации | автор и владелец (админ) | автор; опубликовать может только владелец (админ) |
| Новости, журнал, курсы, Marketplace, мероприятия | все (черновики — владелец) | владелец |
| Creator Studio, задачи, партнёры | владелец | владелец |
| Заказы | покупатель и владелец (админ) | покупатель создаёт «ожидает оплаты», статус меняет владелец (админ) |
| Запись на курс | ученик и владелец (админ) | бесплатный — сам ученик, платный — после подтверждения оплаты |
| Уведомления и приглашения | адресат | отправитель создаёт, адресат отвечает |

Правила задаются RLS-политиками и триггерами в `schema.sql`:

- права администратора есть только у владельца и только пока открыта сессия админки
  (после ввода пароля, на 2 часа);
- пароль админки хранится как bcrypt-хэш в таблице, недоступной через API;
- роль нельзя изменить из приложения; администратор может быть только один;
- 5 неверных паролей — блокировка входа в админку на 15 минут.

Блокировка участников — в «Админ-панель → Пользователи».
Удаление аккаунта из приложения вызывает функцию `atamura_delete_my_account`.

Фото и PDF сейчас хранятся внутри записей. Когда материалов станет много, их стоит перенести
в Supabase Storage (бакет с публичными ссылками) — это следующий шаг развития сервера.
